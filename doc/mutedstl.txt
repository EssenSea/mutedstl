1. INTRODUCTION                            *mutedstl* *mutedstl-intro*

    Clean: the foreground and background are read from the theme, so it
    fits almost any colourscheme; multi-colour statuslines excepted.

mutedstl is a self-contained, deliberately *clean* statusline for Vim 9:
two colours, no colour noise.

It needs NO per-theme colourfile: it reads each colourscheme's own Normal
foreground/background, so built-in and third-party themes work as-is.

It has a colour backend (derives the fg/bg pair) and a statusline front end
(%#group# fragments), and depends only on Vim itself: |hlget()|, |hlset()|,
|v:colornames|.

==============================================================================
2. REQUIREMENTS                                 *mutedstl-requirements*

Vim 9.1 or later with |+vim9script|.

    REQUIRED ~
    |hlget()| / |hlset()|   8.2.3578.  Read Normal, apply highlights.
                             If absent, |mutedstl#HasCapabilities()| is false
                             and the plugin stays dormant.

    OPTIONAL ~
    |v:colornames|  8.2.4774.  |mutedstl#NameToHex()|; empty table -> ''.
    |win_getid()|   8.0.       |mutedstl#IsActive()|; guarded.
    |v:dying|       8.0.       |mutedstl#Redraw()|; guarded.
    OptionSet       autocmd.   Refresh on 'background'; ColorScheme is the
                               common fallback.

Without |+vim9script| the file is simply not sourced.

==============================================================================
3. INSTALLATION                                 *mutedstl-install*

Use it as a Vim package: place this directory under
`pack/{any}/start/mutedstl/` inside a directory in 'packpath', e.g. >

    ~/.vim/pack/mutedstl/start/mutedstl/

or with a plugin manager pointing at the repository.

There is NO dependency to install.

==============================================================================
4. ENABLING                                     *mutedstl-enable*

The plugin does not install the statusline by itself.  Enable it with: >

    call mutedstl#Setup()

(An `import autoload 'mutedstl.vim'` style also works: `import autoload
'mutedstl.vim'` then `mutedstl.Setup()`.  The `mutedstl#Fn()` names are used
here because the 'statusline' expression and autocommands need them anyway.)

Or, to have it enabled automatically when the plugin loads, set this before
the plugin loads (e.g. in your vimrc): >

    let g:mutedstl_auto_setup = 1

A typical vimrc setup: >

    set laststatus=2
    set noshowmode
    let g:mutedstl_invert = 1
    call mutedstl#Setup()

5. OPTIONS                                      *mutedstl-options*

All options live in the `g:mutedstl_` namespace.  Set them before calling
|mutedstl#Setup()|.

                                                 *g:mutedstl_theme*
#theme      string (default '')
            Source theme.  '' means the currently active colourscheme.  Any
            colourscheme name may be given; its Normal foreground/background
            are read (with known transparency switches forced off, so a
            transparent theme still yields an opaque background).  Named
            themes are cached, keyed by theme and 'background'.
            A name that is not an available colourscheme yields 'NONE' colours
            (the plugin never falls back to the previous theme's colours).

                                                 *g:mutedstl_invert*
#invert     number (default 0)
            When non-zero (also any non-empty string), swap foreground and
            background.  The result is coerced to a Boolean.

                                                 *g:mutedstl_fg*
#fg         any (default unset)
            Explicit foreground override.  Accepts a '#RRGGBB' string, a
            colour name, a 256-colour index (number or digit string), or
            'NONE' (transparent).

                                                 *g:mutedstl_bg*
#bg         any (default unset)
            Explicit background override; same accepted formats as #fg.

                                                 *g:mutedstl_prefix*
#prefix     string (default 'Mutedstl')
            Prefix for the generated highlight-group names, so you can avoid
            collisions or match your own naming.  The groups become
            {prefix}Emphasis / {prefix}Ordinary / {prefix}Inactive.

                                                 *g:mutedstl_inactive*
#inactive   string (default 'ordinary')
            Which chunk non-current windows use: 'ordinary' (default, same
            pair as active ordinary) or 'emphasis' (the inverted pair).

                                                 *g:mutedstl_debug*
g:mutedstl_debug
            number (default 0)
            When non-zero, mutedstl emits diagnostics with |:echomsg| for
            recoverable problems that are otherwise silent (for example an
            unknown {kind} passed to |mutedstl#Apply()|).  Off by default so
            normal statusline rendering is never disturbed.

An override that is present but not a usable value falls back to the theme
colour instead of raising an error.  A numeric colour index outside 0..255 is
clamped into range (no error).

==============================================================================
6. HIGHLIGHT GROUPS                             *mutedstl-groups*

|mutedstl#ApplyDefault()| registers three groups:

  MutedstlEmphasis   active window, emphasis chunk (mode, diagnostics)
  MutedstlOrdinary   active window, ordinary chunk (file, right)
  MutedstlInactive   non-current windows; always the ordinary colours

Non-current windows never use the emphasis chunk.

7. PUBLIC API                                   *mutedstl-api*

                                                        *mutedstl#Setup()*
mutedstl#Setup()
        Apply the highlight groups and install the refresh autocommands
        (ColorScheme, OptionSet background, re-assertion on buffer/window
        entry).  It also installs String() as the DEFAULT 'statusline', but
        ONLY when no global 'statusline' is set: an explicit value is never
        overwritten (see |mutedstl-custom|).  The check is on the global
        value, so a window-local 'statusline' in one window does not stop
        other windows from inheriting the default.

                                                        *mutedstl#Refresh()*
mutedstl#Refresh()
        Recompute and apply the highlight groups (called on ColorScheme /
        'background' changes).

                                                        *mutedstl#Redraw()*
mutedstl#Redraw()
        Redraw the statusline, except while |v:dying| is set.

                                                        *mutedstl#String()*
mutedstl#String()
        Return the assembled statusline string.  Used by the 'statusline'
        option via `%!mutedstl#String()`.

                                                        *mutedstl#Mode()*
mutedstl#Mode([{mode}])
        Return a human-readable mode label for |mode()|.  Keyed by the
        leading character (per :h mode(): compare the leading char, not the
        whole string); a few multi-char modes are kept exact.  The optional
        argument overrides |mode()| (mainly for testing; only a string is
        honoured).

                                                        *mutedstl#Paste()*
mutedstl#Paste()
        Return 'PASTE' when 'paste' is set, else ''.

                                                        *mutedstl#IsActive()*
mutedstl#IsActive()
        True when the window being rendered is the current window.

                                                         *mutedstl#Colors()*
mutedstl#Colors()
        Return the resolved colours.  This is a STABLE interface; the field
        names and meanings are meant to stay fixed for other plugins.

            ordinary  [fg, bg]  normal chunk
            emphasis  [fg, bg]  inverted chunk
            inactive  [fg, bg]  non-current-window chunk (g:mutedstl_inactive)
            fg        [gui, cterm]  resolved foreground
            bg        [gui, cterm]  resolved background
            invert    Boolean   true if fg/bg were swapped
            is_none   Boolean   true if a side is transparent

        A [fg, bg] chunk is [[gui, cterm], [gui, cterm]]; 'gui' is '#RRGGBB'
        (or 'NONE') and 'cterm' is a 0..255 index string (or 'NONE').

                                                           *mutedstl#Hi()*
mutedstl#Hi({group}, {chunk})
        Apply one [fg, bg] chunk to highlight group {group} using |hlset()|.
        Throws an error if {chunk} is not [[fg_gui, fg_cterm], [bg_gui,
        bg_cterm]].

                                                           *mutedstl#Apply()*
mutedstl#Apply({groups})
        Apply {group: 'ordinary'|'emphasis'} using the muted colours.

                                                    *mutedstl#ApplyDefault()*
mutedstl#ApplyDefault()
        Apply the default three-group scheme (see |mutedstl-groups|).

                                               *mutedstl#HasCapabilities()*
mutedstl#HasCapabilities()
        Return Vim(true) when this Vim provides the APIs mutedstl needs
        (currently |hlget()| and |hlset()|), else Vim(false).  Other plugins
        can use it before depending on mutedstl's groups.

                                                     *mutedstl#GroupName()*
mutedstl#GroupName({kind})
        Return the highlight group name for a logical kind: 'emphasis',
        'ordinary' or 'inactive'.  Handy for building a custom 'statusline'.

                                                      *mutedstl#GroupMark()*
mutedstl#GroupMark({kind})
        Like |mutedstl#GroupName()| but returns a ready-to-concatenate
        statusline group marker '%#Group#'.  For 'emphasis'/'ordinary' it
        picks the inactive variant when the rendered window is not the current
        window.

                                                        *mutedstl#Chunk()*
mutedstl#Chunk({content} [, {kind}])
        Wrap ANY statusline content in one of the plugin's groups.  {content}
        is passed through verbatim and parsed by Vim's 'statusline' mechanism,
        so it may be a fixed string, any statusline item (e.g. '%t',
        '%<%t%m%r'), or a statusline function (e.g. '%{mutedstl#Mode()}').
        {kind} is a logical name -- 'emphasis', 'ordinary' (default) or
        'inactive' -- resolved via |mutedstl#GroupName()| (honouring
        g:mutedstl_prefix), OR any highlight group name (e.g. 'Error',
        'Warning', 'MyAccent'), which is used verbatim and never switched to
        inactive.  No spaces are added; the result is '%#{group}#{content}'.
        Examples: >
            &statusline = mutedstl#Chunk('%t')
                  \ .. mutedstl#Chunk('%{mutedstl#Mode()}', 'emphasis')
                  \ .. mutedstl#Chunk('%= %y | Buf:%n')
                  \ .. mutedstl#Chunk('%{YourGroup#Status()}', 'Error')
<
        This single function replaces per-item wrappers: since {content} is
        parsed by Vim, every statusline item (see |statusline|) and every
        '%{...}' expression works without extra helpers.
        This single function replaces per-item wrappers: {content} is parsed
        by Vim, so every statusline item and '%{...}' expression works
        without extra helpers.
                                                      *mutedstl#FromTheme()*
mutedstl#FromTheme({theme}, {attr})
        Read a colour pair from a named theme's Normal group.  {attr} must be
        'fg' or 'bg'; {theme} may be '' for the current colourscheme.  Returns
        [gui, cterm].  Throws an error if {attr} is neither 'fg' nor 'bg'.
        Useful for reusing mutedstl's theme-aware colour reading elsewhere
        (statusline, tabline, ...).

                                                          *mutedstl#NrToHex()*
mutedstl#NrToHex({n})
        Convert a 256-colour index to an approximate '#RRGGBB'.  {n} is
        clamped into 0..255, so the result is always a valid colour.

                                                       *mutedstl#HexToCterm()*
mutedstl#HexToCterm({hex})
        Nearest xterm-256 index for a '#RRGGBB' value (min squared RGB
        distance).  Returns -1 when {hex} is not exactly '#RRGGBB' with hex
        digits only.

                                                        *mutedstl#NameToHex()*
mutedstl#NameToHex({name})
        Resolve a colour name to '#RRGGBB' via |v:colornames| ('' if unknown).

                                                      *mutedstl#ReloadCache()*
mutedstl#ReloadCache()
        Drop the theme colour cache.  Call after installing or editing
        colourschemes.

                                                        *mutedstl#Reassert()*
mutedstl#Reassert()
        Clear any stale window-local 'statusline' so the window inherits the
        global one again.

8. CUSTOM STATUSBAR                              *mutedstl-custom*

mutedstl is a colour package: the default layout comes from String(), but you
can lay out your own 'statusline' using its highlight groups.  Set 'statusline'
before calling Setup() (an explicit value is never overwritten):

    &statusline = mutedstl#GroupMark('emphasis')
          \ .. ' %{mutedstl#Mode()}%{mutedstl#Paste()} '
          \ .. mutedstl#GroupMark('ordinary') .. ' %<%f%m%r%=%y | Buf:%n | [%l:%c]'
    call mutedstl#Setup()

The three groups are (see |mutedstl-groups|):
    %#MutedstlEmphasis#   %#MutedstlOrdinary#   %#MutedstlInactive#

Note: use the mutedstl#Mode() / mutedstl#Paste() names (not the import alias)
inside the 'statusline' string, since it is evaluated in Vim's own context.

<mutedstl-plug>  Optional mappings you can map yourself (they run in the
plugin's script context, where the import alias is visible):

    <Plug>(mutedstl-refresh)    re-apply the highlight groups and redraw
    <Plug>(mutedstl-redraw)     redraw only
    <Plug>(mutedstl-reload)     drop the theme cache, re-apply and redraw

Example:   nmap <Leader>mr <Plug>(mutedstl-refresh)

9. NOTES                                        *mutedstl-notes*

- Vim keeps the GUI (guifg/guibg) and cterm (ctermfg/ctermbg) channels
  separate, and a theme author writes both; the theme's cterm value is
  authoritative.  mutedstl reads it first and only approximates the nearest
  xterm-256 colour for a missing side.
- The current theme ('' ) is read directly and never cached; only named
  themes are cached.  The cache is keyed by '{theme}|{background}', so its
  size is bounded by (number of distinct theme names probed) x 2; there is no
  automatic eviction — use |mutedstl#ReloadCache()| to clear it.
- |mutedstl#HexToCterm()| scans the 256-entry palette (O(256), a small
  constant) and is only used as a fallback when a theme provides no cterm
  value.  |mutedstl#NrToHex()| is O(1).
- NrToHex() and HexToCterm() are not exact inverses: a cube colour whose RGB
  equals a system colour (e.g. index 16 == #000000) maps back to the system
  index (0).  The result is visually identical; round-tripping an index is not
  guaranteed.
- The statusline uses lazy %{...} items for |mode()| and 'paste' so they are
  evaluated in the context of the statusline's own window (both are
  window-local; this matters with multiple windows).

Pull requests and bug reports are welcome.  The plugin is kept minimal on

11. COMPATIBILITY                                *mutedstl-compat*

Vim allows runtime files to change behaviour between releases (|design-policy|).
mutedstl instead treats its public surface as a contract and tracks breakages
with tests.

STABLE API ~
                                                *mutedstl-stable-api*
Names, signatures and return structure are kept compatible within a major
version; a change requires a major bump:

    Setup()  Refresh()  Redraw()  Reassert()  ReloadCache()  Colors()  Hi()
    Apply()  ApplyDefault()  FromTheme()  GroupName()  GroupMark()  Chunk()
    String()  Mode()  Paste()  IsActive()  NrToHex()  HexToCterm()  NameToHex()

The shape returned by |mutedstl#Colors()| (field names, [gui, cterm] layout,
Boolean 'invert'/'is_none') is frozen.  The option names under `g:mutedstl_`
(plus `g:mutedstl_debug`, `g:mutedstl_auto_setup`) are STABLE.
                                                *mutedstl-options-stable*

DEPRECATION POLICY ~
                                                *mutedstl-deprecation*
To change or remove a stable item: (1) mark it deprecated here and in the
source; (2) keep the old behaviour and warn under |g:mutedstl_debug|; (3)
remove it only in the next major version.  No items are deprecated today.

SUPPORT MATRIX ~
                                                *mutedstl-support*
Vim 9.1 or later is supported (the current stable line in major
distributions, e.g. Gentoo 9.1.1652).  CI runs on the minimum line
(ubuntu-24.04 Vim, 9.1) and the newest official release.  test/upstream.vim
additionally pins the behaviour of the Vim APIs listed in
|mutedstl-requirements|, so an upstream change fails the build instead of
reaching users.  Without the required APIs the plugin
stays dormant (|mutedstl#HasCapabilities()| is false) and never errors.
